Цей файл доповнює обов'язкові правила [AGENTS.md](AGENTS.md). Технічна карта й передача актуальної роботи містяться у [TECHNICAL_ARCHITECTURE.md](docs/TECHNICAL_ARCHITECTURE.md), [EXTENSIONS.md](docs/EXTENSIONS.md) і [NEXT_AGENT_HANDOFF.md](docs/NEXT_AGENT_HANDOFF.md).

## Мова та стиль

Спілкуйтеся з користувачем українською. Пишіть код, технічні ідентифікатори й Conventional Commit англійською. Коментарі у коді пишіть українською, зберігаючи сталу конвенцію файлу.

Не вигадуйте відгуки дітей, наявність згоди, сумісність, параметри принтера, міцність, тривалість друку або приймання всього каталогу. Станом на 2026-10-07 повне приймання контенту позначене INCOMPLETE: 4/101 конфігурацій мають фінальний PASS, 97 очікують огляду, 13 оригінальних знімків збережено. Фізичний друк і враження дітей — Not verified. Для поточного стану посилайтеся на [звіт](docs/FUN_CONTENT_REVIEW.md) та [coverage manifest](verification/content-evidence/coverage.json).

## Перед змінами

- Перевірте git status, історію потрібних файлів та фактичні залежності.
- Збережіть лише свою область змін; не перезаписуйте роботу іншого виконавця.
- Не додавайте CDN, зовнішні шрифти, runtime-пакети, мережеві запити, TypeScript, bundler, linter чи ES modules.
- Тримайте модулі як IIFE на window.*. Не редагуйте lib/three.min.js.
- Зберігайте порядок script-тегів: реєстр, місії, стани, генератори, контент-паки, UI-модулі, SceneManager, app.js останнім.
- UI-зміни узгоджуйте між index.html, app.js та відповідним локальним CSS. Перед новим data-* зв'язком перевірте контракт у AGENTS.md.
- Зміни місій і пресетів проводьте через ContentRegistry. Зберігайте стабільні ID/key/modelKey і відмінність між місією, записом моделі та конфігурацією. Деталі є в [EXTENSIONS.md](docs/EXTENSIONS.md).
- Додайте перевірку поведінки тільки для зміненої логіки, з урахуванням точного бюджету з AGENTS.md. Документації достатньо статичних перевірок; не запускайте application suites для документаційної зміни. Не обходьте обмеження іншим runner.
- Для UI перевіряйте реальну взаємодію та видимий результат. Якщо перевірка завершилась тайм-аутом або втратила прогрес, зробіть одну обмежену спробу скасування, перегляньте логи й позначте результат INDETERMINATE; не вбивайте й не перезапускайте браузер або Editor власника. CLI timeout не доводить зупинку in-process тесту.
- Відокремлюйте локальні статичні, детерміновані, браузерні, файлові, слайсерні, фізичні та дитячі докази.

## Розробка

StudioApp керує проєктними транзакціями та обробниками UI. Поточні параметри зчитуються з DOM-контролів, кешованих у StudioApp._domCache; serializeState().controls є їхнім знімком у JSON. Не створюйте паралельний StudioApp.controls або this.controls. Лише MinecraftForgeGenerator має окремі getState()/setState() для сітки й палітри. SceneManager володіє переданою THREE.Group та її ресурсами. Не обходьте ці власники прямими викликами з нових UI-кнопок.

Для нової властивості JSON оновіть ProjectState нормалізацію, дозволені значення, межі та зворотну сумісність. Не плутайте version релізу з schemaVersion файлу. Новий генератор має повертати THREE.Group через build3D(params); його скрипт завантажується до app.js.

Сцена використовує міліметри: 1 одиниця Three.js = 1 мм. Binary STL — це результат експорту геометрії, а не доказ manifold або успішного друку. Екранні ефекти не можна оголошувати фізично точними.
