# Технічна архітектура

Актуальний зріз документації: **3D Club Studio v1.9.0**, формат проєкту **schemaVersion 1**. Версія застосунку й версія формату файлу незалежні. Після змін звіряйте цей опис із джерелом у [index.html](../index.html), [app.js](../src/app.js), [ProjectState](../src/projectState.js), [ContentRegistry](../src/contentRegistry.js) та [SceneManager](../src/sceneManager.js).

## Архітектурні межі

Застосунок працює на звичайних HTML, CSS і JavaScript без кроку збірки. Three.js r128 завантажується з lib/three.min.js. Модулі використовують IIFE і публікують класи або об'єкти на window. Runtime-пакети, CDN, зовнішні шрифти та мережеві сервіси не є частиною контракту.

Інтерфейс має чотири вкладки: minecraft, illusion, physics і mob. StudioApp керує вибраною вкладкою, транзакціями проєкту, автозбереженням і запуском місій. Значення параметрів живуть у DOM-контролах, кешованих у StudioApp._domCache; serializeState().controls є їхнім знімком у JSON. Генератори створюють THREE.Group; SceneManager додає її до сцени, кадрує та звільняє ресурси попередньої групи.

Масштаб сцени — міліметри: 1 одиниця Three.js = 1 мм. Стіл Anycubic у сцені є орієнтиром розміру. Сам по собі він не доводить сумісність геометрії з принтером.

## Порядок завантаження

Теги в index.html формують граф залежностей. Зберігайте чинний порядок і завантаження app.js останнім:

1. lib/three.min.js
2. src/voxelFont.js, src/soundEffects.js, src/safeStorage.js, src/historyManager.js

## Місії, моделі й пресети

Реєстр зараз містить 72 місії: базові й Adventure Pack місії та 48 нових авторських. Нові моделі розподілені на 20 рельєфів, 12 персонажів, 8 оптичних і 8 інженерних робіт. Нові місії відкриваються в режимі одного пластику.

Ці числа описують різні рівні каталогу:

- **Місія** має числовий ID і стабільний namespaced key. Вона зберігає завдання та початковий config для одного з чотирьох генераторів.
- **modelKey** є стабільним ключем запису моделі в каталозі. Він не є ані числовим ID місії, ані ключем пресета.
- **Пресет** — це вхідні дані генератора; для Minecraft — сітка та кольори. Місія може посилатися на нього через config.mcPreset або presetKey.
- **Скінченна конфігурація** — конкретний набір параметрів, який інвентаризує coverage manifest. Один задум може мати кілька конфігурацій; кілька місій можуть посилатися на вже наявний пресет чи дизайн.

Поточний маніфест перелічує 101 конфігурацію, з яких 48 позначено як нові авторські моделі. Це не кількість місій, не оцінка унікальних фізичних виробів і не доказ успішного друку. Не створюйте дублікати місій лише для того, щоб додати синонім моделі. Правила й приклади розширення наведені в [EXTENSIONS.md](EXTENSIONS.md).

## Збереження проєкту

ProjectState.SCHEMA_VERSION дорівнює 1. JSON має app: 3d-club-studio, schemaVersion, activeTab, дані Minecraft, controls та інформацію про активну місію. Відсутній schemaVersion означає старий формат v1; невідома або майбутня версія відхиляється. Значення version — метадані релізу, а не версія схеми.

Нові збереження містять activeMissionKey разом з activeMissionId. Стабільний ключ — основна ідентичність; старі файли з числовим ID мігрують через реєстр. Неіснуючий ключ, неоднозначний ID, невідомий таб, невалідна сітка чи параметр відхиляються до застосування. Нормалізація повертає від'єднані дані, тож імпортування не повинно частково змінити поточний проєкт.

Minecraft зберігає 16 рядків по 16 висот 0–4 і кольори для активних рівнів. Числові поля мають скінченні межі й кроки, перелічені в ProjectState; для застарілих числових значень застосовується сумісна нормалізація. Teacher state помічника заняття зберігається окремо.

Імпорт і старт місії проходять через StudioApp, яка фіксує попередній стан для undo та синхронізує UI, генератор, місію й автозбереження. Не обходьте цей власник прямим викликом генератора з UI-кнопки.

## Побудова й експорт геометрії

Кожен генератор має build3D(params) і повертає THREE.Group. Перед передачею групи SceneManager перегляньте, хто володіє її геометріями й матеріалами: після setModel() SceneManager очищає попередню модель і її ресурси.

Binary STL-експорт проходить по mesh у модельній групі, пропускає об'єкти з userData.exportable === false, перетворює координати сцени у формат STL, центрує XY та ставить нижню точку на Z=0. Екранні ефекти фізичних демонстрацій перебувають окремо й не є частиною виробу; перед експортом фізична демонстрація скидається. Позначка exportable сама по собі не засвідчує замкнутість сітки, допустимі нависання або міцність.

Паспорт і блоки каталогу показують допоміжні виміри й відомості. Час друку підтверджується тільки записом із зовнішнього слайсера. Кодова оцінка чи екранна симуляція не є виміром друку або фізичної сили.

## CSS та UI

Головний документ — index.html. Спільні стилі містяться в styles.css; додаткові стилі полиці пригод, інструментів рельєфу й помічника мають окремі файли у корені. Перед додаванням елемента перевірте його фактичні класи, data-* атрибути та обробник у src/app.js. Для повторюваних зв'язків використовуйте чинні data-* контракти з AGENTS.md.

Робочі цільові розміри — 1366×768 і 1024×768. Кнопки дій у верхній панелі мають залишатися доступними; довгий підзаголовок може ховатися за медіа-правилом. Діалоги мають залишатися прокручуваними й мати доступне закриття.
