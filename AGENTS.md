# AGENTS.md — правила роботи в 3D Club Studio

Ці правила доповнюють технічні контракти у [docs/TECHNICAL_ARCHITECTURE.md](docs/TECHNICAL_ARCHITECTURE.md), [docs/EXTENSIONS.md](docs/EXTENSIONS.md) і [docs/NEXT_AGENT_HANDOFF.md](docs/NEXT_AGENT_HANDOFF.md). Перед зміною вихідного коду перевірте Git status, поточну реалізацію та вузькі файли-власники. Не перезаписуйте незв'язану роботу.

Команди оболонки запускайте через RTK за правилами @C:\Users\igors\.codex\RTK.md. Технічні ідентифікатори, код і коміти пишіть англійською; спілкуйтеся з користувачем українською.

## 1. Завершення та версії

Після завершення задачі перевірте Git status, приберіть лише власні тимчасові файли, додайте тільки потрібні шляхи, створіть змістовний Conventional Commit англійською та виконайте git push origin main. Суто документаційна задача не потребує зміни версії продукту. Для функціональних змін визначте, чи випускається нова версія, і тоді синхронізуйте всі місця нижче.

Якщо випускається нова версія, синхронізуйте всі місця:

| Файл | Контракт |
|---|---|
| index.html | app-version-pill і app-version-corner |
| src/app.js | поле version у serializeState() |
| src/passportPrintController.js | версія у підвалі renderRetinaCanvas() |
| README.md | заголовок версії та назва редакції |

Версія релізу — метадані застосунку. ProjectState.SCHEMA_VERSION окремо визначає JSON-формат і змінюється лише разом із відповідною міграцією.

## 2. Офлайн-платформа

Студія працює на локальних HTML, CSS і JavaScript та вбудованій Three.js r128 у lib/three.min.js. Не додавайте зовнішні CDN, шрифти, аналітику, runtime-запити, збирачі, npm-залежності, ESLint, Prettier або інший новий runtime чи lint tooling. Не переводьте модулі на TypeScript або ES modules. Скрипти — локальні IIFE, які публікують публічний API на window.

Не редагуйте lib/three.min.js. Перевіряйте роботу з реальним локальним вихідним кодом, а не з припущеннями про сторонню бібліотеку.

## 3. Скрипти й власники

Порядок тегів у index.html є контрактом залежностей. Поточна послідовність:

~~~text
lib/three.min.js
src/voxelFont.js → src/soundEffects.js → src/safeStorage.js → src/historyManager.js
src/contentRegistry.js → src/missionManager.js → src/projectState.js
src/modalFocus.js → src/snapshotCompareController.js → src/passportPrintController.js
src/generators/minecraftForge.js → dualIllusion.js → physicsMechanics.js → mobMutator.js
src/content/adventurePack.js → funReliefs.js → funDiscoveries.js → funEngineering.js
src/adventureShelf.js → src/pixelEditorTools.js → src/lessonCompanion.js
src/sceneManager.js → src/app.js
~~~

Завантажуйте app.js останнім. Контент-паки реєструються після ContentRegistry, базових місій і генераторів, але до побудови UI. Новий скрипт додавайте лише після перевірки його window.* залежностей.

StudioApp керує вкладками, історією проєкту, місіями, імпортом/експортом JSON, автозбереженням і зв'язками UI. Поточні значення параметрів генераторів читаються з DOM-контролів через _domCache; serializeState() записує їхній знімок у JSON-поле controls. Не вводьте паралельний this.controls. SceneManager володіє переданою THREE.Group і ресурсами сцени. Лише MinecraftForgeGenerator має getState()/setState() для сітки й палітри.

## 4. Каталог і сталі ідентичності

Станом на 2026-10-07 активний реліз — v1.9.0, схема — 1. У каталозі 72 навчальні місії та 48 нових авторських моделей: 20 рельєфів, 12 персонажів, 8 оптичних і 8 інженерних робіт. Нові місії запускаються в одноколірному режимі.

Не ототожнюйте три числа: mission ID/key позначає навчальне завдання; modelKey позначає запис моделі; пресет і controls визначають конкретну конфігурацію генератора. У verification/content-evidence/manifest.json є 101 конфігурація. Місія може використовувати наявний пресет, а конфігурація може бути варіантом наявного задуму. Не описуйте 101 як число місій або як 101 фізично прийнятий виріб.

Поточне приймання авторського каталогу — INCOMPLETE: фінальний PASS мають 4/101 конфігурації, 97 очікують огляду; поточний пакет містить 13 оригінальних знімків. Друк, міцність, сумісність зі слайсером і дитяче приймання мають статус Not verified. Перевіряйте docs/FUN_CONTENT_REVIEW.md і coverage.json до будь-якого твердження про якість або готовність.

Кожна місія має додатний числовий ID і незмінний namespaced key. Нові modelKey унікальні. Не виводьте ID з довжини списку й не повторно використовуйте історичні значення. Валідуйте імпорт через ProjectState.normalize() до зміни UI. Детальні правила паків та міграцій описані в [EXTENSIONS.md](docs/EXTENSIONS.md).

## 5. UI, CSS і доступність

Основні стилі у styles.css; додаткові модулі мають adventure-shelf.css, pixel-editor-tools.css і lesson-companion.css. Перевіряйте наявні селектори та обробники перед додаванням нових класів або DOM-зв'язків. Для елементів використовуйте чинні data-* атрибути:

| Атрибут | Призначення |
|---|---|
| data-tab | вкладки minecraft, illusion, physics, mob |
| data-mc-preset | вибір пресета Майнкрафт-Кузні |
| data-mc-brush | пензлі висот 0–4 |
| data-il-preset | пресети Оптичного Перевертня |
| data-camera-view | ракурси iso, front, top, side, side90, bottom |
| data-view-mode | editor, split, viewport |
| data-insert-sym | вставка воксельного символу |
| data-mission-check | перевірки size, connected, mono |
| data-mission-filter | фільтри каталогу, значення див. у index.html |

Не вводьте data-cam-view у новому коді — це застарілий дублікат data-camera-view.

Повторювані UI-компоненти мають використовувати узгоджені класи: картки .card/.panel-card з .card-header та .card-header-actions; сітки пресетів .preset-grid/.presets-grid з .preset-btn/.preset-mini-btn; панелі пензлів .brush-bar/.brush-palette з .brush-btn; символи .sym-bar з .sym-btn; значення .control-val/.control-val-badge; зв'язність .connectivity-pill з модифікаторами .warn, .danger або .bridged. Перевіряйте стилі перед додаванням класу та оформлюйте :hover, :active, .active і видимий стан фокусу.

Основні робочі екрани: 1366×768 і 1024×768. У верхній панелі кнопки дій мають залишатися доступними: нижче 1550px приховується довгий brand-subtitle; нижче 1366px застосовуються компактні відступи та скрол без обрізання; нижче 1120px і 768px групування стає компактним, необов'язкові підписи ховаються. Діалоги мають залишатися прокручуваними, мати обмеження висоти до 90vh і кнопку швидкого закриття ✕. Для UI-зміни перевіряйте саму взаємодію та її результатний стан, а не лише виклик callback.

## 6. Камера, аудіо, друк і STL

### Камера

Камера використовує сферичні координати й плавну інтерполяцію; підтримує перспективну й ортографічну проєкції. Перемикання проєкції доступне через toggleProjection() і клавіші O/5. Для ізометричного ракурсу ortho використовує Math.atan(Math.SQRT2) (приблизно 54.74°), перспектива — приблизно 60°. setCameraView('iso') скидає ціль панорамування до (0, 18, 0) і обирає найкоротший шлях азимутального обертання. Ручна взаємодія зі сценою через sceneManager.onUserCameraInteraction має знімати .active-cam з кнопок пресетів камери. Підтримувані ракурси: iso, front, top, side, side90, bottom.

### Аудіо

window.StudioSound — готовий інстанс, а не клас. Виклики звуку мають перевіряти ініціалізацію й бути захищені від винятків. AudioContext створюється або поновлюється лише після взаємодії користувача (click, keydown або touchstart). Цільовий masterGain — близько 0.70, щоб звук було чути на тихих ноутбуках; перевіряйте фактичний код перед заявою про поточний рівень. Кнопки #btn-toggle-sound і #btn-toggle-music мають узгоджувати текст і стани .muted та .playing зі звуковим станом.

| Стан | Кнопка | Клас | Текст |
|---|---|---|---|
| Звук увімкнено | #btn-toggle-sound | .btn-sound | 🔊 Звук |
| Звук вимкнено | #btn-toggle-sound | .btn-sound.muted | 🔇 Звук: ВИМК |
| Музика грає | #btn-toggle-music | .btn-music.playing | 🎵 Мелодія: ГРАЄ |
| Музика зупинена | #btn-toggle-music | .btn-music | 🎵 Музика |

### Print-safe цілі та STL

Масштаб сцени — 1 одиниця Three.js = 1 мм. Базова підкладка та підтримки залежать від конкретного генератора й конфігурації; не обіцяйте їх для всіх моделей. Таблиця 200×200 мм Anycubic i3 Mega — орієнтир у сцені, не доказ сумісності.

Для піксельних і воксельних моделей ціль приймання — суцільна підкладка щонайменше 1.0 мм і відсутність непідтриманих висячих островів; генератор може будувати містки чи внутрішні опори відповідно до своєї геометрії. Це інженерна ціль, а не доказ виконання для кожної конфігурації чи фізичного результату.

SceneManager створює Binary STL, центрує X/Y і ставить нижню точку на Z=0; mesh з userData.exportable=false пропускаються. Екранні снаряди й мішені фізичних демонстрацій — не фізичний прогноз і не частина експортованої моделі. Успішна побудова STL не доводить manifold, допуски, підтримки, міцність або успішний друк. Час друку беріть із реального слайсера.

## 7. Бюджет перевірок власника

Для звичайних змін запускайте лише перевірки, що покривають змінену поведінку. Для документації достатні статичні перевірки, а не application test suites. Не обходьте обмеження іншим runner або heavy-run flag.

- Одна партія — максимум 20 знайдених випадків і 60 секунд. Для невеликого виправлення загальний бюджет — 180 секунд.
- В інтерактивному Unity Editor використовуйте один точний фільтр за тестом або fixture; одна партія EditMode — до 60 секунд, PlayMode — до 120 секунд. Не запускайте нефільтровані, assembly-wide, усі режими, benchmark, stress, soak, multi-seed або довгі симуляції за замовчуванням.
- Перед тестом невідомої вартості спершу перегляньте його джерело. Тести UI мають проходити справжню дію та перевіряти новий стан.
- Якщо тест завершився тайм-аутом, втратив відгук або не показує прогрес, спробуйте одне обмежене скасування, перегляньте журнали та позначте результат INDETERMINATE. Не ставте повторні тести в чергу, не вбивайте й не перезапускайте браузер або Editor власника; CLI timeout не доводить, що in-process тест зупинився.
- Повні або важкі перевірки належать до заздалегідь запланованого запуску поза робочим Editor власника. Відкладені релізні перевірки називайте прямо.

## 9. Чек-лист завершення

- [ ] Змінені файли відповідають власному scope; немає тимчасових або сторонніх змін.

- [ ] Жодних runtime-залежностей чи непідтверджених заяв про друк, дітей або повне приймання не додано.
